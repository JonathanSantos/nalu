# Nalu language reference

This is the reference for Nalu v1: the syntax and meaning of every construct, the failure model, commands, script parameters, tests, the `nalu` tool and every diagnostic. The compiler is the source of truth: if this page and `nalu` disagree, one of them has a bug.

New to Nalu? Start with [Getting started](getting-started.md). Related pages:

- [stdlib.md](stdlib.md): every module, type and function, generated by `nalu doc --all`. This page shows only the parts the language needs.
- [recipes.md](recipes.md) and [`../examples/`](../examples/): complete scripts ([`hello`](../examples/hello.nalu), [`backup`](../examples/backup.nalu), [`deploy`](../examples/deploy.nalu), [`installer`](../examples/installer.nalu), [`release`](../examples/release.nalu) and its [tests](../examples/release_test.nalu)).
- [vision.md](vision.md) and [decisions.md](decisions.md): why Nalu is the way it is. [architecture.md](architecture.md): how the compiler works.
- [README.md](README.md): the index of the docs.

Every `nalu` code block on this page is a complete program that passes `nalu check` and `nalu fmt --check`. Blocks marked `text` or `console` are fragments, generated output, or code that is meant to fail.

## Principles

1. **One source, several scripts.** The compiler writes one readable, deterministic script per target: Bash 4.3+ for Linux, Bash 3.2 for macOS, PowerShell 5.1+ for Windows. Nothing has to be installed where the script runs.
2. **Fail loud by default.** Anything that can fail (a command, a file, the network, a conversion) stops the script with a precise message unless you handle it. Handling is explicit and always uses the same keyword: `catch`.
3. **Commands are first-class.** `$ git pull` runs a program, `{x}` is always exactly one argument, `$( )` captures output and `if $ cmd {` tests an exit code.
4. **Honest on every target.** What a system lacks is either emulated with the same behavior or rejected at compile time. Nothing fails silently.
5. **Small and regular.** 27 keywords and one way to do each thing. No `import`, no `;`, no `throws`, no `null`.

## Scripts and lexical structure

### A script

```nalu
// 1. Parameters (optional) come first.
/// where to save the files
param dest: path = "~/backups"

// 2. Functions and types, in any order. They can be used before they are declared.
fn greet(name: str) -> str {
    return "hello, {name}"
}

// 3. Top-level statements run in order, from top to bottom.
print(greet("world"))
print("saving to {dest}")
```

- The file is the program. There is no `main` and no `import`: the standard library (`fs`, `log`, `http`…) is always available.
- `param`, `fn`, `struct`, `enum` and `test` appear only at the top level. `param` lines come before anything else (`E005`).
- Source files are UTF-8 with the `.nalu` extension; a leading BOM is ignored.
- Use `snake_case` for variables, functions, fields and parameters, and `PascalCase` for structs and enums. A type name must start with an uppercase letter for its literal (`Service { … }`) to parse.

### Lines and statements

There is one statement per line and no `;` (`E006`). A statement continues on the next line when the line ends with an operator, `,`, `(`, `[`, `{`, `=>`, `->`, `:` or `catch`, or when the next line starts with `.`:

```nalu
let words = ["delta", "alpha", "charlie"]
let sorted = words
    .filter(w => w.len() > 4)
    .sort()
    .join(", ")
let total = 1 +
    2
let home = env.get("HOME") catch
    "unknown"
print(sorted, total, home)
```

### Comments

```nalu
// A line comment.
/* A block comment,
   over several lines. */

/// A doc comment describes the declaration below it.
/// Consecutive lines are joined with a space.
fn twice(n: int) -> int {
    return n * 2
}

print(twice(21))
```

Doc comments on a `param` become its `--help` text; on a function, editors show them on hover.

### Names

Names use ASCII letters, digits and `_`, and don't start with a digit. Other characters may appear only in strings and comments (`E005`). Keywords and reserved names (`os`, `err`, `print`, module names such as `fs` or `path`…) can't name variables, parameters, functions or types (`E004`); the full lists are in [Keywords and grammar](#keywords-and-grammar).

### Literals

| Literal | Examples | Type |
|---|---|---|
| integer | `42`, `-7`, `1_000_000`, `0xFF` | `int` |
| duration | `500ms`, `30s`, `1.5s`, `1m30s`, `2h`, `7d` | `duration` |
| text | `"hello {name}"`, `'raw'`, `"""…"""` | `str` |
| bool | `true`, `false` | `bool` |
| list | `[1, 2, 3]`, `[]` | `[]T` |
| map | `{ "api": 8080 }`, `{}` | `map[K]V` |
| struct | `Service { name: "api", port: 8080 }` | the struct |
| enum case | `Env.prod` | the enum |

There are no floating-point numbers: `1.5` is an error (`duration without a unit`).

## Types and values

| Type | Holds | Notes |
|---|---|---|
| `str` | text | UTF-8; compared and sorted by code point |
| `int` | 64-bit integer | `/` truncates toward zero |
| `bool` | `true` or `false` | conditions only take `bool` |
| `path` | a file or folder path | `/` joins; see [Paths](#paths) |
| `duration` | a length of time | stored in milliseconds; never mixes with `int` |
| `secret` | text that is never shown | see [Secrets](#secrets) |
| `[]T` | a list: `[]str`, `[]int`, `[]Service`, `[][]str` | see [Lists and maps](#lists-and-maps) |
| `map[K]V` | a map: `map[str]int`, `map[Env]str`, `map[str][]str` | keys `str`, `int` or an enum; values scalars or lists of scalars |
| struct | a record with fields and methods | see [Structs and methods](#structs-and-methods) |
| enum | one of a fixed set of cases | see [Enums](#enums) |

*Scalars* are `str`, `int`, `bool`, `path`, `duration` and enums. Types are written like in Go: `[]str`, `map[str]int`. The older `str[]` and `map<str, int>` are errors (`E006`) with a hint.

- **Conversions are explicit.** Text to a number: `"42".to_int()`, which can fail. Anything scalar to text: interpolation, `"{n}"`. `str` and `path` convert to each other automatically where one is expected.
- **There is no `null`.** A missing value is a failure: `env.get("X")` fails when `X` is not set, and you handle it with `catch` (see [Failures](#failures)).
- **There is no function type.** Functions aren't values; lambdas exist only as arguments (see [Lambdas](#lambdas)).
- **Values are copies.** Assigning or passing a list, map or struct copies it; changing the copy never changes the original.

```nalu
var original = [1, 2]
var copy = original
copy.push(3)
print(original.len(), copy.len())  // 2 3
```

### Durations and units

`duration` and `int` never mix, and the compiler checks every operation:

| Expression | Result |
|---|---|
| `duration + duration`, `duration - duration`, `duration % duration` | `duration` |
| `duration * int`, `int * duration`, `duration / int` | `duration` |
| `duration / duration` | `int` |
| `duration + int`, `d > 0`, `d == 5` | error `E020`: write the unit, as in `d > 0ms` |

```nalu
let timeout = 1m30s
let step = 250ms
print("{timeout} is {timeout / 1s} seconds")  // 1m30s is 90 seconds
print(timeout + step, timeout * 2)            // 1m30.25s 3m
print(timeout / step)                         // 360
if timeout > 1m {
    print("more than a minute")
}
```

- Compound literals go from the largest unit to the smallest (`1d2h`, `1m30s`, `1h30m15s250ms`). Only seconds take a fraction, down to milliseconds (`1.5s`, `0.25s`).
- As text, a duration shows its non-zero units: `0s`, `250ms`, `1.5s`, `1m30s`, `1d2h`.
- For a number, divide by a unit: `d / 1s` (whole seconds), `d / 1ms`. A bare `{d}` as a command argument is an error (`E021`): write `{d / 1s}` in the unit the program expects.
- Points in time are `int`: `time.now()` and `fs.modified(p)` are Unix seconds, `time.now_ms()` is milliseconds. `time.since(t)` gives the `duration` since `t`.

## Variables

```nalu
let name = "nalu"      // cannot change (the default)
var tries = 0          // can change
let port: int = 8080   // with an explicit type
var names: []str = []  // an empty list needs a type
tries += 1
names.push(name)
print(name, tries, port, names.len())
```

- `let` can't be reassigned or changed in place (`push`, `pop`, `remove`, `xs[i] = v`, `m[k] = v`, `s.field = v`): that is `E002`. `var` can. There is no `const` (`E006`).
- Every variable starts with a value: `let x` alone is an error.
- The type is inferred. Annotate it when an empty `[]` or `{}` needs one, or when it helps the reader.
- A variable that is never read is a warning (`W001`), not an error; assigning to it doesn't count as reading. Names that start with `_` are exempt.
- Declaring a name twice in the same block is `E003`. A nested block or a function can declare a name that exists outside; inside, the inner one wins.
- Top-level variables are visible in functions. Functions can read them and change the ones declared with `var` (counters, accumulators). `parallel` bodies and lambdas can't change outside variables.
- Function parameters and loop variables can't be assigned (`E002`): copy them into a `var`.
- There is no `++` or `--` (`E006`): use `x += 1`. The compound assignments are `+=`, `-=`, `*=`, `/=` and `%=`. Assignments are statements, not expressions.

## Operators

From the highest precedence to the lowest:

| Level | Operators | Notes |
|---|---|---|
| 1 | `x.field`, `x.method()`, `xs[i]`, `f()` | access and calls |
| 2 | `-x`, `!x` | `!` takes a `bool` |
| 3 | `*`, `/`, `%` | `/` also joins paths |
| 4 | `+`, `-` | `+` concatenates when either side is `str` |
| 5 | `..`, `..=` | ranges, only in `for` and `match` |
| 6 | `==`, `!=`, `<`, `<=`, `>`, `>=` | can't be chained (`a < b < c`) |
| 7 | `&&` | short-circuit; `bool` on both sides |
| 8 | `\|\|` | short-circuit; `bool` on both sides |
| 9 | `value \| $ cmd` | sends a value to a command's input |
| 10 | `catch` | handles a failure; right-associative |

- There are no `and`, `or` and `not`: write `&&`, `||` and `!`. Using any of them as an operator is `E006` with a hint, and the three words are reserved names (`E004`).
- There is no ternary `? :` and no `??` (`E006`). Use `if` as an expression, and `catch` for a default value.
- `==` and `!=` need operands of the same type (`E011`); `str` and `path` count as the same. Lists, maps, structs and secrets can't be compared: compare fields or lengths (`xs.len() == 0`).
- `<`, `<=`, `>` and `>=` compare numbers, durations or text. Text compares by code point on every target, without locale rules: `"B" < "a"` is `true`.
- `int / int` truncates toward zero and `%` takes the sign of the left side: `-7 / 2 == -3` and `-7 % 2 == -1`.
- Conditions are strict: `if n {` is an error (`E010`). Write `n != 0`, `s != ""`.
- Division and remainder by zero fail with `division by zero` on every target; `--explain` lists each `/` and `%` whose divisor can be zero. Handle it like any failure: `a / b catch 0`.
- `+` with a `str` on either side turns the other side into text: `"port " + 8080` is `"port 8080"`.
- `path / str` (and `path / path`) is the only operator overload. You can't define operators.

## Strings

```nalu
let user = "ana"
let tasks = ["build", "test"]
let greeting = "hello, {user}! {tasks.len()} tasks: {tasks.join(", ")}"
let raw = 'C:\Users\{not interpolated}'
let braces = "{{literal braces}} and \{ these \}"
let report = """
    user: {user}
      tasks: {tasks.len()}
    """
print(greeting)
print(raw)
print(braces)
print(report)
print(fmt("{} has {} tasks", user, tasks.len()))
```

The output:

```text
hello, ana! 2 tasks: build, test
C:\Users\{not interpolated}
{literal braces} and { these }
user: ana
  tasks: 2
ana has 2 tasks
```

| Form | Interpolation | Escapes | Lines |
|---|---|---|---|
| `"…"` | `{expr}` | `\n \t \r \" \\ \{ \}` | one |
| `'…'` | no | no | one; can't contain `'` |
| `"""…"""` | `{expr}` | as in `"…"` | several |

- **Interpolation.** `{expr}` takes any expression that becomes text: `str`, `path`, `int`, `bool`, `duration`, an enum or `err`, including calls and nested strings (`{tasks.join(", ")}`). Lists, maps and structs don't become text (`E022`, with a suggestion such as `list.join(", ")`), and neither do secrets (`E050`).
- **Literal braces.** `{{` and `}}` are literal braces, and so are `\{` and `\}`. An empty `{}` is also literal, which is what `fmt` templates use.
- **Escapes.** Only the ones in the table; any other is `E005`. `\0` is rejected because Bash can't store the NUL character.
- **Raw strings.** Single quotes are for regular expressions, Windows paths, JSON and other shells' code: what you write is what you get.
- **Multi-line strings.** `"""` removes the line break after the opening quotes, the line that holds the closing quotes, and the indentation common to every line. The result doesn't end with a line break.
- **`fmt(template, items…)`** replaces each `{}` with the next item. It has no format specifiers; for alignment use `pad_left` and `pad_right`. When the template is fixed text, the compiler checks the number of items (`E012`).
- **Characters.** `.len()`, `.slice()`, `.index_of()` and `.chars()` count Unicode code points, the same on every target.
- **`slice(start, end)`** works like JavaScript's: `end` is optional, a negative index counts from the end, and out-of-range values are clamped, so it never fails. `"abcd".slice(0, -1)` is `"abc"` and `"abcd".slice(-2)` is `"cd"`. Lists have the same `slice`.
- **No indexing.** `s[0]` is an error (`E010`): use `s.slice(0, 1)` or `s.chars()[0]`.
- **Methods** have Python and Rust semantics: `replace` replaces every occurrence, `split` keeps empty fields. The full list is in [stdlib.md](stdlib.md#type-str).

To write JSON, use single quotes for fixed text and `json.quote` for values; it adds the quotes and escapes:

```nalu
let name = "Ana \"the admin\""
let fixed = '{"role": "admin"}'
let built = "{{\"name\": {json.quote(name)}}}"
print(fixed, built)  // {"role": "admin"} {"name": "Ana \"the admin\""}
```

## Control flow

```nalu
param force: bool

let free_mb = 800
if free_mb < 1_000 && !force {
    log.warn("low disk space: {free_mb} MB")
} else if os == "macos" {
    log.info("macOS with enough space")
} else {
    log.info("enough space")
}

let replicas = if force { 6 } else { 1 }
let label = if replicas > 1 {
    let extra = replicas - 1
    "1 + {extra} replicas"
} else {
    "1 replica"
}
print(label)
```

- Conditions take no parentheses, braces are required, and the condition must be a `bool` (`E010`).
- `if` is an expression when you use it as a value. Then `else` is required (`E010`), every branch has the same type, and each branch is an expression or a block whose last line is the value.

```nalu
let files = ["a.txt", "b.txt"]
let ports = { "api": 8080, "web": 3000 }

for file in files {
    print(file)
}
for i, file in files {  // with the index, from 0
    print(i, file)
}
for name, port in ports {  // in insertion order
    print(name, port)
}
for n in 0..3 {  // 0, 1, 2
    print(n)
}
for n in 1..=3 {  // 1, 2, 3
    print(n)
}

var tries = 0
while tries < 10 {
    tries += 1
    if tries % 2 == 0 {
        continue
    }
    if tries > 5 {
        break
    }
    print("try {tries}")
}
```

- `for x in list` goes over the items; `for i, x in list` adds the index. A map needs both names, `for key, value in map` (`E010`). A range gives one name.
- `a..b` excludes `b`; `a..=b` includes it. Ranges exist only in `for` and in `match` arms.
- `break` and `continue` act on the innermost loop. They don't cross `retry`, `parallel` or a lambda (`E046`).
- `print(a, b, …)` writes the items to standard output, separated by spaces, with a line break at the end. For messages, use `log.info`, `log.warn`, `log.error` and `log.debug`, which write to standard error.
- `exit(code)` ends the script (`exit()` is `exit(0)`) after running every pending `defer`. Codes outside 0 to 255 are reduced modulo 256. `exit` is a statement, not a function call you can use as a value.
- An expression on its own line that does nothing, such as `x + 1`, is `E030`.
- A command can be a condition: `if $ git diff --quiet {` (see [Commands as conditions](#commands-as-conditions)).

## `match`

```nalu
enum Env { dev, stage, prod }

let target = Env.stage
match target {
    prod        => print("6 replicas")
    dev | stage => print("1 replica")
}

let file: path = "release.tgz"
let kind = match file.ext {
    "tgz" | "gz" => "tar"
    "zip"        => "zip"
    _            => fail "unsupported format: {file}"
}

let status = 404
match status {
    200..300 => log.info("ok")
    404      => log.warn("not found")
    _ => {
        log.error("unexpected status")
        fail "status {status}"
    }
}
print(kind)
```

- Each arm is `pattern => result`, one per line, without commas. The arms are tried from the top; the first that matches runs.
- **Patterns** are literals (`str`, `int`, `duration`, `bool`), integer ranges (`200..300`, `0..=11`, `-10..0`), enum cases written without the type name (`prod`, not `Env.prod`), and `_`, which matches anything. `|` joins alternatives.
- **Names, guards and structs** (below): a name takes the value, `if` adds a condition, and `Type { field: pattern }` looks inside a struct.
- **No fallthrough.** The right side is an expression, a statement (`fail`, `return`, `break`, `continue`, a command…) or a block.
- **Exhaustive on enums.** A `match` on an enum must cover every case or have `_`; `E031` lists the missing ones. A `match os` with `"linux"`, `"macos"` and `"windows"` is exhaustive, and so is `true` and `false` on a `bool`.
- **An expression.** Used as a value, every arm has the same type (an arm that fails fits any type) and a block arm gives its last line. If the arms don't cover every value, `_` is required (`E031`). As a statement, a `match` on text or numbers may leave values out; nothing runs for them.
- A struct literal in an arm used as a value needs its type name, because `{` right after `=>` opens a block: `major => Version { major: 1, minor: 0, patch: 0 }`.
- `match` takes text (`str` or `path`), `int`, `duration`, `bool`, enums and structs (`E010` for anything else).
- An arm after one that matches everything (`_` or a name, without `if`) would never run (`E031`).

### Names, guards and struct patterns

```nalu
struct Service {
    name: str
    port: int
    tags: []str
}

fn describe(status: int) -> str {
    return match status {
        200..=299     => "ok"
        n if n >= 500 => "server error {n}"
        n             => "status {n}"
    }
}

fn kind(s: Service) -> str {
    return match s {
        Service { port: 443 }                   => "https"
        Service { port: p } if p < 1024         => "privileged port {p}"
        Service { tags: t } if t.contains("db") => "database"
        Service { name: n }                     => "service {n}"
    }
}

print(describe(503), kind(Service { name: "pg", port: 5432, tags: ["db"] }))
```

- **A name** (`n => …`) matches any value and takes it, for the arm and its `if`. It is alone in its arm (no `|`). On an enum a name is always a case, so a typo is an error (`E001`) and not a new variable; use `_` there.
- **A guard** (`pattern if condition => …`) runs the arm only when the condition is also true; otherwise the next arms are tried. An arm with `if` never counts toward covering the cases, so an enum or a `match` used as a value still needs the other arms or `_`.
- **A struct pattern** (`Service { port: 443, name: n }`) names the type and some fields; the fields left out can be anything. A field takes a literal, a range, an enum case, `_`, or a name that takes the field's value. Fields that are lists or maps only take `_` or a name.

A `match` on an enum that misses cases:

```console
$ nalu check deploy.nalu
error[E031]: `match` does not cover every case of `Env`: missing cases `dev`, `stage`
  --> deploy.nalu:4:1
  |
4 | match target {
  | ^
  = help: add the missing arms or `_ => …`
```

## Functions

```nalu
/// Builds a greeting; `times` repeats the mark.
fn greet(name: str, times: int = 1, mark: str = "!") -> str {
    return "hello, {name}" + mark.repeat(times)
}

/// Only has an effect, so it declares no return type.
fn announce(message: str) {
    log.info(message)
}

fn factorial(n: int) -> int {
    if n <= 1 {
        return 1
    }
    return n * factorial(n - 1)
}

print(greet("ana"))                   // hello, ana!
print(greet("ana", times: 3))         // hello, ana!!!
print(greet(name: "bob", mark: "?"))  // hello, bob?
announce("factorial of 10: {factorial(10)}")
```

- `-> T` declares the return type; without it the function returns nothing. With it, every path ends in `return` or `fail` (`E032`).
- Parameters can have defaults, and parameters without a default come first (`E012`). Arguments are positional or named (`times: 3`); any parameter can be named, and positional arguments come before named ones (`E012`).
- **There is no `throws`.** A function that contains something that can fail, without `catch`, can fail too, and its callers treat it like any other fallible call. The compiler works this out; `nalu check --explain` shows every place (see [Failures](#failures)).
- Parameters and return values can be of any type: scalars, secrets, structs, lists (`[]str`, `[]Service`) and maps. They are passed and returned by value.
- Functions can read top-level variables and change the top-level ones declared with `var`.
- Functions aren't values: `let f = greet` is `E033`.
- Recursion is allowed. Methods are functions declared inside a `struct` (see [Structs and methods](#structs-and-methods)).

## Lambdas

```nalu
struct Service {
    name: str
    port: int
}

let services = [Service { name: "api", port: 8080 }, Service { name: "web", port: 3000 }]
let nums = [5, 1, 4, 2]

let big = nums.filter(n => n > 2)
let names = services.map(s => s.name)
let web = services.find(s => s.name == "web") catch services[0]
let labels = nums.map(n => {
    if n > 3 {
        return "high"
    }
    return "low"
})
let by_port = services.sort_by(s => s.port)
print(big.join(","), names.join(","), web.port, labels.join(","), by_port[0].name)
print(nums.any(n => n > 4), nums.all(n => n > 0))
```

- A lambda is `x => expression`, or `x => { … }` with `return`. It takes one parameter.
- Lambdas exist only as the argument of `filter`, `map`, `any`, `all`, `find` and `sort_by`. Anywhere else, such as in a variable, they are `E033`.
- A lambda reads outside variables but can't change them (`E033`).
- `map` must return a scalar; `sort_by` sorts by an `int` or `str` key, and keeps the order of equal keys.

## Lists and maps

### Lists

```nalu
var names: []str = []
names.push("api")
names.push("web")
let first = names[0]
let missing = names[9] catch "none"
names[1] = "worker"
let last = names.pop() catch ""
print(first, missing, last, names.len(), names.contains("api"))
print([3, 1, 2].sort().join(","), [1, 1, 2].unique().len(), [1, 2, 3].sum())
```

- `xs[i]` and `xs[i] = v` fail when `i` is out of range: `index 9 is out of range (the list has 2 items)`. There are no negative indexes: use `xs.last()`.
- `push` and `pop` change the list, so they need a `var`. `pop`, `first`, `last` and `find` fail when there is nothing to return.
- `filter`, `map`, `sort`, `sort_by`, `reverse`, `slice` and `unique` return a new list. `join` and `sort` need a list of scalars; `sum` adds a `[]int` or a `[]duration`.
- Lists can't be added with `+` (`E010`): `push` the items instead.
- In a command, a list on its own (`$ rm -- {files}`) becomes one argument per item.

### Lists of lists

```nalu
var grid: [][]int = [[1, 2], [3, 4]]
grid[1][0] = 30
grid[0].push(5)
for row in grid {
    print(row.join(" "))
}
let sizes = grid.map(row => row.len())
let pairs = [1, 2, 3].map(n => [n, n * n])
print(sizes.join(","), pairs[2][1], grid.contains([30, 4]))
```

- A list can hold lists of scalars: `[][]str`, `[][]int`. Everything that works on a list works on the outer one, and an item is a list you can index, loop over and pass around.
- Items are values: `let row = grid[0]` is a copy. To change an item in place, write the whole path: `grid[1][0] = 30`, `grid[0].push(5)`. The same works for fields and map values: `services[0].port = 80`, `groups["go"].push(file)`.
- `contains`, `index_of` and `unique` compare whole lists. `join`, `sort` and `sum` need scalars, so use them on the items.
- Lists of maps and three levels of lists are planned (`E090`).

### Maps

```nalu
var ports = { "api": 8080, "web": 3000 }
let empty: map[str]int = {}

ports["worker"] = 9090
ports.remove("web")
let api = ports["api"] catch 0
if ports.has("worker") {
    print("there is a worker")
}
for name, port in ports {
    print(name, port)
}
print(api, ports.len(), ports.keys().join(","), empty.len())
```

- A map literal's keys are values, such as `{ "api": 1 }`, `{ 404: "not found" }` or `{ Env.prod: 6 }`. A literal with bare names, `{ api: 1 }`, is a struct.
- `m[k]` fails when the key doesn't exist (`key 'x' does not exist`): add `catch` for a default, or check `m.has(k)` first. `m[k] = v` adds or replaces and never fails.
- Keys are `str`, `int` or an enum; values are scalars or lists of scalars (`map[str][]str`). Maps with map values are planned (`E090`).
- To add to a list in a map, the key must exist: `if !groups.has(k) { groups[k] = [] }`, then `groups[k].push(x)`.
- `for k, v in m`, `keys()` and `values()` follow insertion order. `remove` on a missing key does nothing.
- An empty `{}` needs a type from an annotation or the context (`E044`).

## Structs and methods

```nalu
struct Service {
    name: str
    port: int
    replicas: int = 1  // a default
    tags: []str = []   // lists and maps of scalars can be fields
    labels: map[str]str = {}

    fn url() -> str {
        return "http://localhost:{self.port}"
    }

    fn scaled(n: int) -> Service {
        return Service { ..self, replicas: self.replicas * n }
    }
}

let api = Service { name: "api", port: 8080 }
var services: []Service = [api, { name: "web", port: 3000 }]
services.push(Service { name: "worker", port: 9090, replicas: 2 })
let other = Service { ..api, port: 9090 }

var copy = api
copy.port = 1  // `api` doesn't change

print(api.url(), api.scaled(3).replicas, other.port, copy.port)
print(services[1].name, api.tags.len())
```

A struct can hold another struct:

```nalu
struct Port {
    number: int
    proto: str = "tcp"
}

struct Service {
    name: str
    port: Port
}

struct Config {
    env: str
    services: []Service
}

var api = Service { name: "api", port: Port { number: 80 } }
api.port.number = 8080
let p = api.port  // a copy
var cfg = Config { env: "prod", services: [api] }
cfg.services.push(Service { name: "web", port: Port { number: 3000 } })
cfg.services[1].port.proto = "udp"
print(api.port.number, p.proto, cfg.services.len(), cfg.services[1].port.proto)
```

- **Literals** are `Type { field: value }`. When the type is already known (an annotation, a parameter, an item of a typed list, a return value), you can leave the name out: `{ name: "web", port: 3000 }`. Without that context, it's `E044`.
- Fields without a default are required (`E012` lists the missing ones). `..base` fills every field you don't write from `base`.
- **Methods** are `fn` declarations inside the struct. They read the value through `self`, which is always explicit and read-only (`E002`); to "change" a value, return a new one with `..self`.
- Structs are values: assigning copies. The fields of a `var` can be assigned.
- Fields are scalars, other structs, lists of structs, lists of scalars or of lists, and maps with scalar or list values. A struct can't contain itself, directly or through other structs or lists (`E010`).
- The items of a list-of-structs field (`services: []Service`) can have scalars, lists of scalars and structs of those as fields; an item with a map field is planned (`E090`).
- `a.b.c = v` changes a nested field of a `var` in place, and so do `cfg.services[0].port = 80` and `cfg.services.push(s)`.
- A struct doesn't become text (`E022`): interpolate its fields.
- There is no inheritance, no classes and no interfaces.

## Enums

```nalu
enum Env { dev, stage, prod }

let target = Env.parse("prod") catch Env.dev
let replicas = match target {
    prod        => 6
    dev | stage => 1
}
print("{target}: {replicas} replicas", target == Env.prod)  // prod: 6 replicas true
```

- Cases are written with the type, `Env.prod`, except in `match` arms. Cases are separated by commas or line breaks.
- As text (interpolation, command arguments) a case is its name: `prod`.
- `Type.parse(text)` converts text to a case and fails when no case has that name: `'qa' is not a valid Env (use: dev, stage, prod)`.
- Enums can be compared with `==`, used as map keys and used as `param` types, where the flag accepts only the case names (`--env <dev|stage|prod>`).

## Paths

```nalu
let config = dirs.config("nalu")
let log_file = config / "app.log"
let key = dirs.home() / ".ssh" / "id_ed25519"
let bundle: path = "dist/app.tar.gz"

print(bundle.name, bundle.stem, bundle.ext, bundle.parent)  // app.tar.gz app.tar gz dist
print(log_file)
if fs.exists(key) {
    print("{key.name}: {fs.size(key)} bytes")
}
```

- `/` joins paths with the system's separator. The left side must be a `path`: `str / str` is `E043`, so annotate the first one (`let base: path = "dist"`) or start from a function that returns a `path`, such as `dirs.home()`.
- A `str` converts to a `path` wherever a `path` is expected.
- **Properties** have no parentheses: `name` (the last component), `stem` (without the extension), `ext` (the extension without the dot; `""` if there is none, and dotfiles have none) and `parent`. They only look at the text and never fail.
- **The disk is in `fs`:** `fs.exists(p)`, `fs.is_dir(p)`, `fs.is_file(p)`, `fs.size(p)` and `fs.modified(p)`. The last two fail when the path doesn't exist.
- **`~`.** A path that starts with `~` or `~/` means your home folder, the same way on every target: the standard library expands it (`fs.read("~/.netrc")`), and so does a command, both for a word you type unquoted (`$ ls ~/bin`) and for a `path` value in `{p}`. In quotes it is plain text: `$ echo '~'` prints `~`.

## Regular expressions

```nalu
let line = "release v1.24.3 on 2026-11-09"
if regex.test(line, '^release ') {
    let version = regex.find(line, 'v\d+\.\d+\.\d+')
    let date = regex.groups(line, '(\d+)-(\d+)-(\d+)')
    print(version, date.join("/"))  // v1.24.3 2026/11/09
}
print(regex.find_all("a1 b22 c333", '\d+').join(","))  // 1,22,333
print(regex.replace("a.b.c", '\.', "/"))               // a/b/c
let port = regex.find(line, ':\d+') catch ""           // no match: fails
print(port == "")
```

The pattern is fixed text written in the call, in single quotes so that `\` stays as it is (`E054` otherwise). The compiler checks it and translates it for each target (POSIX ERE for Bash, .NET for PowerShell), writing out everything the engines would otherwise decide on their own, so a pattern matches the same text everywhere.

| Pattern | Matches |
|---|---|
| `a`, `\.`, `\(` | that character; put `\` before any of `\ . * + ? \| ( ) [ ] { } ^ $ / -` |
| `.` | any character, newline included |
| `[abc]`, `[a-z0-9_]`, `[^,]` | one of the characters, or any but them; ranges only between ASCII characters |
| `\d`, `\w`, `\s` | `[0-9]`, `[A-Za-z0-9_]`, and space, tab, newline, `\r`, `\v`, `\f` (ASCII only); `\D`, `\W`, `\S` are the opposite |
| `\n`, `\t`, `\r` | newline, tab, carriage return |
| `x*`, `x+`, `x?`, `x{3}`, `x{2,}`, `x{2,5}` | repetition, always as many as possible (up to 255) |
| `( … )` | a group: `regex.groups` returns what each one matched (`""` if it took no part) |
| `a\|b` | either one |
| `^`, `$` | the start and the end of the whole text; only at the start and the end of the pattern |
| `(?i)` at the start | ASCII letters in either case |

Lazy repetition (`*?`), `(?:…)`, back-references, `\b` and POSIX classes such as `[[:alpha:]]` don't exist; `E054` says what to write instead.

**One way to match.** Bash's engine returns the longest match and .NET's the first one its search finds. They agree whenever the pattern can read a text in only one way, so `find`, `find_all`, `groups` and `replace` accept only such patterns (`E054`). In practice: what follows a repetition starts with a character the repetition can't read (`^([^=]*)=(.*)$`, not `^(.*)=(.*)$`; `[^/]*/`, not `.*/`), the branches of `|` start differently (`(dev|prod)`, not `(a|ab)`), and a repeated group has no group inside it. `regex.test` accepts any valid pattern, because whether a match exists never depends on the engine.

- `find_all` and `replace` need a pattern that can't match empty text.
- `replace` inserts its third argument as it is: `$1` is just text.
- `find` and `groups` fail when there is no match; `find_all` returns an empty list.
- For Base64 there is [`encoding`](stdlib.md#module-encoding): `encoding.base64_encode(text)` and `encoding.base64_decode(text)`.

## Failures

Failure handling is the heart of Nalu. One rule covers every case, and one keyword handles it.

### The rule: what can fail stops the script

```nalu
let text = fs.read("version.txt")   // if this fails, the script stops here
$ git push                          // so does this
let version = text.trim().to_int()  // and this
print(version)
```

There is no `try` on every line, no `?`, no `throws` and no `set -e`. An operation that can fail and has no `catch` passes the failure on:

| Where the failure happens | What happens |
|---|---|
| in a function | the function fails with the same error, and the same rule applies to its caller |
| at the top level | the script prints `error: <message>` to standard error and exits with the error's code (1 by default) |
| inside `try { }` | the rest of the block is skipped and the `catch` handler runs |
| inside `retry` | the block runs again; after the last attempt, `retry` fails with the last error |
| inside `parallel` | the other tasks finish, then `parallel` fails with every error |
| inside a `test` | the test fails with the error's message |

You can read any line and know what happens if it fails: the same as on every other line.

### What can fail

- `$` commands (a non-zero exit code, or a program that isn't found) and `$( )` captures.
- `fail`.
- Standard library functions marked **can fail** in [stdlib.md](stdlib.md), such as `fs.read`, `env.get` and `http.get`.
- `.to_int()`, `.find()`, `.first()`, `.last()` and `.pop()`.
- `xs[i]` and `xs[i] = v` with an index out of range, and `m[k]` with a missing key.
- `Type.parse(text)`.
- `retry`, after its last attempt, and `parallel`, when a task fails.
- Your own functions that contain any of these without `catch`.

Division and remainder fail too when the divisor can be zero (`a / b`, `a % b` with a `b` that isn't a non-zero literal): `division by zero`, the same on every target. Nothing else fails: other arithmetic, comparisons, string methods other than `to_int`, `slice`, path properties, `fs.exists`, `m[k] = v`.

### Handling a failure: `catch`

| Form | What it does |
|---|---|
| `x catch value` | uses `value` instead, of the same type: `fs.read(p) catch ""` |
| `x catch fail "…"` | fails with a better message, where `{err}` is available: `catch fail "offline: {err}"` |
| `x catch ignore` | carries on; only for things that return no value (commands, calls without a return type) |
| `x catch { … }` | runs the block with `err`; used as a value, the block's last line is the value |
| `a catch b catch c` | tries from left to right; it groups as `a catch (b catch c)` |

```nalu
fn parse_port(text: str) -> int {
    let port = text.to_int()
    if port < 1024 {
        fail "port {port} is reserved", code: 3
    }
    return port
}

let user = env.get("USER") catch env.get("USERNAME") catch "someone"
let tmp = fs.temp_dir() catch fail "could not create a temporary folder: {err}"
let port = parse_port("80") catch {
    log.warn("{err} (code {err.code}); using 8080")
    8080
}
$ git pull catch {
    log.warn("offline ({err.code}), using the cache")
}
fs.rm(tmp) catch ignore
print(user, port)
```

- `catch` only follows something that can fail (`E040`). For a logical "or" between conditions, use `||`; the compiler suggests it when it sees `catch` between two `bool` values.
- `catch` has the lowest precedence of all: `fs.read(p) == "a" catch false` means `(fs.read(p) == "a") catch false`.
- A `catch` block may end with `return`, `fail`, `exit(…)`, `break` or `continue` instead of a value. These need the block: write `catch { return }`, not `catch return` (`E005`).
- `err` exists only inside `catch { … }` and in the message of `catch fail "…"` (`E046` anywhere else, including after `catch value`).
- `catch ignore` on a command that changes files (`rm`, `mv`, `rmdir`, `del`, `Remove-Item`) is a warning (`W012`): handle the failure or let it propagate.

### Blocks: `try { } catch …`

```nalu
let version = "1.4.0"
try {
    $ git add CHANGELOG.md
    $ git commit -m "release {version}"
    $ git tag v{version}
} catch {
    log.error("could not tag the release: {err}")
    exit(err.code)
}

try { fs.move("build", "dist") } catch fail "could not move the build: {err}"
```

- When any line inside `try` fails, the rest of the block is skipped and the handler runs. The handler takes the same forms as `catch`, except a value: `try` returns nothing.
- `try` without `catch` is `E041`, because failures already propagate. `try` before an expression (`try f()`) is `E006`.
- `return`, `break` and `continue` work inside `try`. Names declared inside it stay inside it.

### The error: `err`

| Field | Holds |
|---|---|
| `err.message` | the text; `{err}` shows it |
| `err.code` | the exit code: 1 by default, a command's own exit code (127 when the program isn't found), or the `code:` given to `fail` |

The messages are the same on every target, for example:

```text
command `git push` failed with exit code 1
command `deploy-tool` was not found
index 9 is out of range (the list has 2 items)
key 'web' does not exist
'12x' is not an integer
environment variable API_TOKEN is not set
fs.read: 'version.txt' does not exist
```

When a command fails, whatever it wrote to standard error is already on the terminal.

### Failing on purpose: `fail`

```nalu
fn check_port(port: int) {
    if port < 1 || port > 65_535 {
        fail "port {port} is out of range"
    }
    if port < 1024 {
        fail "port {port} needs root", code: 77
    }
}

check_port(8080)
$ git pull catch {
    log.warn("git pull failed; giving up")
    fail err
}
```

- `fail "message"` fails with exit code 1; `fail "message", code: n` sets the code. The message is text (`E010` otherwise).
- `fail err`, inside a handler, passes on the error being handled with its message and code.
- `fail` is a statement: on its own line, as a `match` arm or after `catch`. The older `fail("message", code: 3)` is `E006`.

### Seeing what can fail: `nalu check --explain`

Implicit propagation leaves one question open: can this line stop the script? `--explain` lists every place that can fail without `catch`, and where the failure goes:

```console
$ nalu check --explain examples/deploy.nalu
examples/deploy.nalu:44:5: `$ docker` can fail → `publish` fails
examples/deploy.nalu:45:5: `$ docker` can fail → `publish` fails
examples/deploy.nalu:47:5: `$ kubectl` can fail → `publish` fails
examples/deploy.nalu:48:5: `$ kubectl` can fail → `publish` fails
examples/deploy.nalu:53:5: `retry` can fail → `wait_healthy` fails
examples/deploy.nalu:70:1: `$ docker` can fail → the script stops
examples/deploy.nalu:76:1: `parallel` can fail → the script stops
examples/deploy.nalu:86:5: `wait_healthy` can fail → the script stops
8 places can fail without `catch`
functions that can fail: publish, wait_healthy
```

With `--json`, the same list comes as data (see [The `nalu` tool](#the-nalu-tool)). The [VS Code extension](../editors/vscode/README.md) marks these lines in the editor.

## Commands

### `$` runs a program

```nalu
let image = "registry.example.com/api"
let tag = "1.4.0"
let files = ["a.log", "b.log"]

$ git pull
$ docker build -t {image}:{tag} .
$ kubectl set image deployment/api api={image}:{tag}
$ gzip -- {files}
$ git log --oneline > history.txt
```

A line that starts with `$ ` is a command: the program and its arguments, up to the end of the line. The arguments follow a few rules:

- **Unquoted words are literal.** `-t`, `.` and `deployment/api` are passed as written. There is no shell expansion: `*`, `$HOME`, `;` and `&&` reach the program as they are. Use `fs.glob` for wildcards and `env.get` for variables. The one exception is a word that is `~` or starts with `~/`: the `~` becomes the home folder.
- **Each `{expr}` is one argument**, whatever it contains: spaces, `;`, `$` or quotes. There is no word splitting.
- **A word that mixes text and `{ }`** (`api={image}`, `./{name}`) is one argument.
- **A list alone in `{ }`** becomes one argument per item. Mixed with text it's `E042`; for a single argument, write `{xs.join(",")}`.
- **Quoted text is one argument.** Double quotes interpolate (`"release {tag}"`); single quotes don't (`'{}'` is a literal `{}`). `''` is an empty argument. An empty `{}` is literal too, as in `find . -exec rm {} +`.
- **Durations and secrets.** A bare duration (`{d}`) is `E021`: write `{d / 1s}`. A secret as an argument is a warning (`W011`); send it through the input instead.
- **Pipes and redirection.** `|` connects programs, and `>`, `>>`, `2>`, `2>>`, `<` and `2>&1` redirect. A pipeline fails when any of its programs fails. Redirected output keeps the program's exact bytes on every target.
- **Where a command ends.** At the end of the line; at an unquoted ` catch `, which starts the handler; at a `//` comment; and at a `{` that ends the line, which opens a block. To pass the word `catch` as an argument, quote it: `"catch"`. A `}` on the same line is just an argument, so a command inside a block goes on its own line.
- **No shell operators.** `||` inside a command is an error (`E005`): to run another program when one fails, put it in a `catch { … }` block. `&&` is just an argument: put the next command on its own line, where it runs only if the first one succeeded.

### `$( )` captures output

```nalu
let commit = $(git rev-parse --short HEAD)
let tag = $(git describe --tags --abbrev=0) catch "none"
print("{commit} {tag}")
```

- The value is the program's standard output without the trailing line breaks. Its standard error goes to the terminal.
- A capture ends at its closing `)` on the same line, and follows the same argument rules.
- Captures run even with `--dry-run`, because the script needs their values. Keep commands that change things out of `$( )`.

### `value | $ cmd` sends input

```nalu
param token: secret

let manifest = fs.read("deploy.yaml")
manifest | $ kubectl apply -f -
token | $ docker login registry.example.com --username ci --password-stdin
```

The value goes to the program's standard input exactly as it is, without an extra line break at the end. This is how a secret reaches a program.

### Commands as conditions

```nalu
if $ git diff --quiet {
    print("the working tree is clean")
}
while !$ nc -z localhost 5432 {
    log.info("waiting for the database")
    time.sleep(1s)
}
```

- `if $ cmd {` and `while $ cmd {` test the exit code: 0 is `true`. `!` negates it. A condition never fails.
- The command takes the rest of the line, so `&&` can't join it to another condition: nest the `if` instead.
- The `{` must end the line (a one-line block such as `if $ cmd { print("x") }` also works).
- Conditions run even with `--dry-run`.

### Dependencies

After reading its parameters and before running anything, each script checks that every program it runs by a fixed name exists. With [`examples/deploy.nalu`](../examples/deploy.nalu) on a machine without Docker:

```console
$ ./dist/deploy.macos.sh --version 1.4.0   # NALU_TOKEN is set
error: this script needs: docker, kubectl
```

The exit code is 127. Programs named by a path (`./build.sh`) or by a value (`$ {tool}`) aren't checked, nor are shell built-ins (`cd`, `echo`, `test`, `[`, `true`, `false`, `printf`, `read`, `exit`, `export`, `set`, `unset`). Programs in a branch for another system (see [`os`](#code-for-each-system-os-and-native)) aren't required, and `--dry-run` skips the check.

A program you only use when it is there is optional: inside `if proc.exists("x") { … }` (or the `else` of `if !proc.exists("x")`), `x` isn't required and gets no `W010`:

```nalu
if proc.exists("brew") {
    $ brew upgrade
} else {
    log.info("no Homebrew, skipping")
}
```

### Portability: `W010`

`nalu check` compiles for all three targets and warns when a program doesn't exist on one of them:

```console
$ nalu check release.nalu
warning[W010]: program `head` does not exist on Windows
  --> release.nalu:2:31
  |
2 | $ git log --oneline {range} | head -n 20
  |                               ^^^^
  = help: use the standard library (`fs`, `str`…) or put this inside `if os != "windows" { … }`
```

The Unix-only list is `grep`, `sed`, `awk`, `head`, `tail`, `cut`, `tr`, `wc`, `sort`, `uniq`, `xargs`, `find`, `chmod`, `chown`, `ln`, `ps`, `kill`, `sudo`, `brew`, `apt-get`, `apt`, `dnf`, `yum`, `pacman` and `apk`; the Windows-only list is `winget`, `choco` and `scoop`. Prefer the standard library (`fs.replace`, `str.lines()`, `fs.chmod`), or put the command in a branch for the systems that have it.

`$ echo` works the same everywhere: the Windows script writes the line itself instead of calling PowerShell's `echo`. On Windows, every program runs through `System.Diagnostics.Process`, with arguments quoted for the Windows command line and the exit code checked; `.cmd` and `.bat` programs run through `cmd.exe`.

## Code for each system: `os` and `native`

```nalu
match os {
    "linux"   => $ sudo apt-get install -y git
    "macos"   => $ brew install git
    "windows" => $ winget install Git.Git
}

if os != "windows" {
    $ chmod +x run.sh
}
print("running on {os}")
```

- `os` is a **compile-time constant**: `"linux"`, `"macos"` or `"windows"`. The branches that don't apply are left out of each generated script, which is why the commands above don't trigger `W010`.
- Comparing `os` with anything else is `E051` (`os == "widows"` suggests `"windows"`). A `match os` with the three names is exhaustive.
- [`installer.nalu`](../examples/installer.nalu) uses `os` to pick the archive format and the executable name.

`native` inserts shell code as is, as a last resort for what the standard library can't do:

```nalu
native {
    bash: 'ulimit -n 4096'
    powershell: '[Console]::OutputEncoding = [Text.Encoding]::UTF8'
}
print("done")
```

The code is fixed text, without interpolation (use single quotes), and is not checked. Both `bash:` and `powershell:` are required (`E052`).

## `defer`

```nalu
fn announce(what: str) {
    log.info("cleaning up {what}")
}

fn build() {
    defer announce("first")   // runs last
    defer announce("second")  // runs first
    $ make
}

let tmp = fs.temp_dir()
defer fs.rm(tmp)
build()
```

- A deferred call runs when the function ends, or when the script ends for a top-level `defer`. It runs on every way out: `return`, a failure, `exit()` and Ctrl+C. Several `defer`s run in reverse order.
- `defer` takes one call or one simple command, without `|`, redirection or `catch` (`E010`).
- The arguments are evaluated when the `defer` line runs, not at the end.
- A failure inside a deferred call is ignored, so it needs no `catch`.

On Linux and macOS this is an `EXIT` trap (Ctrl+C exits with 130, `TERM` with 143); on Windows, `try { } finally { }`.

## `retry` and `parallel`

### `retry`

```nalu
let url = "https://example.com/health"
retry(10, every: 5s) {
    let status = http.status(url, timeout: 5s)
    if status != 200 {
        fail "answered {status}"
    }
}
log.info("healthy")
```

- `retry(n, every: d) { … }` runs the block until it doesn't fail, at most `n` times, waiting `d` between attempts (`every` defaults to `1s`). After the last attempt, `retry` fails with the last error, which you can handle with `catch`.
- The block is a loop: it can change outside variables, and `return` works inside it. `break` and `continue` don't cross it.
- `retry` returns no value (`E010`): declare a `var` before it and assign it inside.

### `parallel`

```nalu
fn compress(folder: str) -> int {
    $ tar -czf {folder}.tgz {folder}
    return fs.size("{folder}.tgz")
}

let folders = ["docs", "photos", "projects"]

parallel for folder in folders {
    $ tar -tzf {folder}.tgz
}

let sizes = parallel(max: 2) for folder in folders {
    compress(folder) catch 0
}

parallel {
    $ make frontend
    $ make backend
}
print("{sizes.sum()} bytes")
```

- `parallel for x in list { … }` runs one task per item; `parallel { … }` runs each statement of the block as a task.
- Used as a value, `parallel for` gives a list with each task's last line, in the order of the input list (not the order they finish). Each result is a scalar or a struct; lists and maps are planned (`E090`).
- `max:` limits how many tasks run at once (less than 1 counts as 1); the default is `sys.cpus()`.
- When tasks fail, `parallel` waits for all of them, then fails with every message in task order: `parallel: error 1; error 2`. Handle it with `catch` like anything else.
- Tasks can read outside variables but can't change them, and can't `return` (`E045`). `parallel for i, x in …` isn't supported (`E090`).

On Linux and macOS, tasks run as background jobs; on Windows, in a pool of runspaces. Each task gets its own copy of the script's variables, and an `exit` inside a task ends only that task. On Windows, tasks that call `sys.cd` or `env.set` (the folder and the environment belong to the whole process) run one at a time. [`backup.nalu`](../examples/backup.nalu) compresses folders with `parallel(max: 4)`.

## Script parameters

`param` declares a command-line option. Together with `///` comments, it gives every script a `--help`:

```nalu
/// environment to deploy to
param target: Target = Target.dev
/// version to publish, e.g. 1.4.0
param version: str
/// how many copies to run
param replicas: int = 2
/// folders to upload
param folders: []str = ["docs"]
/// also clear the cache
param clear_cache: bool
/// time between health checks
param wait: duration = 30s
/// registry token
param token: secret

enum Target { dev, stage, prod }

log.info("deploying {version} to {target} with {replicas} replicas: {folders.join(", ")}")
if clear_cache {
    log.info("clearing the cache")
}
log.info("checking every {wait}; {args.len()} extra arguments")
token | $ docker login registry.example.com --username ci --password-stdin
```

```console
$ nalu run deploy.nalu -- --help
usage: deploy --version <str> --token <secret> [options] [args…]

  --target <dev|stage|prod>  environment to deploy to (default: dev)
  --version <str>            version to publish, e.g. 1.4.0 (required)
  --replicas <int>           how many copies to run (default: 2)
  --folders <[]str>          folders to upload (default: docs)
  --clear-cache              also clear the cache
  --wait <duration>          time between health checks (default: 30s)
  --token <secret>           registry token (required; or set NALU_TOKEN)
  --dry-run                  show what would happen, without running commands or changing files
  --verbose                  print each command before running it
  -h, --help                 show this help
```

- `param` lines come first in the file (`E005`). Their types are `str`, `int`, `bool`, `path`, `duration`, `secret`, an enum, `[]str`, `[]int` or `[]path` (`E010` otherwise).
- The flag is the name with dashes: `clear_cache` becomes `--clear-cache`. Values go as `--x value` or `--x=value`; lists as `--folders a,b,c`.
- A `bool` is a switch: `--x` sets it and `--x=false` clears it. It is `false` unless the `param` says `= true`.
- A parameter without a default is required, except a `bool`. A default is a fixed value (`E010`).
- `int`, `duration` and enum values are validated before the script runs.
- Arguments that aren't options, and everything after `--`, go to the constant `args: []str`.
- Every script also has `--dry-run`, `--verbose` and `-h`/`--help`, so `dry_run`, `verbose` and `help` can't be parameter names (`E004`). The constant `dry_run: bool` tells the script whether it is a dry run.
- A `secret` parameter is also read from the environment variable `NALU_` plus its name in uppercase (`registry_token` reads `NALU_REGISTRY_TOKEN`), and it can't have a default (`E050`).
- A parameter that is never used is a warning (`W002`).

Usage errors exit with code 2, print the message to standard error, and add a pointer to `--help`:

```console
$ nalu run deploy.nalu -- --version 1.4.0 --target qa
error: --target must be one of: dev, stage, prod (got 'qa')
run with --help to see the options
```

The messages are the same on every target:

```text
error: --version is required
error: --token is required (or set NALU_TOKEN)
error: --version needs a value
error: unknown option: --verbos
error: --replicas must be an integer (got 'x')
error: --wait must be a duration like 30s, 1m30s or 500ms (got '5')
error: --clear-cache takes true or false (got 'maybe')
error: --target must be one of: dev, stage, prod (got 'qa')
```

## Secrets

```nalu
/// token for the registry (or set NALU_REGISTRY_TOKEN)
param registry_token: secret

let db_password = secret(env.get("DB_PASSWORD") catch "")
let api_token = ui.password("API token: ")

registry_token | $ docker login registry.example.com --username ci --password-stdin
db_password | $ psql --host db --username app
let me = http.get("https://api.example.com/me", bearer: api_token)
print(json.get(me, "name"))
```

A `secret` comes from a `secret` parameter, from `secret(text)` or from `ui.password(question)`. It is text that never shows:

- It never becomes text: `print`, interpolation, `fmt` and `+` are `E050`. It can't be compared (`E011`).
- `--verbose` and `--dry-run` show it as `******`.
- It leaves the script only through a command's input (`token | $ cmd`), through the `bearer:` argument of the `http` functions, or as the argument of a function that takes a `secret`.
- As a command argument it is a warning (`W011`): arguments are visible to other users in the process list.

## `--dry-run` and `--verbose`

| Flag | Effect |
|---|---|
| `--dry-run` | `$` commands and standard library writes (`fs.write`, `fs.rm`, `fs.copy`, `http.download`, `http.post`…) are printed to standard error instead of run |
| `--verbose` | every command, captures included, is printed to standard error before it runs (`+ git pull`), with its values filled in; `log.debug` writes |

```nalu
/// where to install
param dest: path = "./out"

let tmp = fs.temp_dir()
defer fs.rm(tmp)
fs.write(tmp / "notes.txt", "built by nalu")
let tag = $(git describe --tags) catch "v0.0.0"
$ cargo build --release
fs.mkdir(dest)
fs.copy("target/release/app", dest / "app")
log.debug("built from {tag}")
log.info("app {tag} installed in {dest}")
```

```console
$ nalu run install.nalu -- --dry-run --verbose
+ git describe --tags
[dry-run] cargo build --release
[dry-run] fs.mkdir ./out
[dry-run] fs.copy target/release/app ./out/app
debug: built from v1.4.0
info: app v1.4.0 installed in ./out
```

- Reads run with `--dry-run`: `$( )` captures, command conditions, `fs.read`, `http.get`…
- Writes inside a folder or file created by `fs.temp_dir()` or `fs.temp_file()` in the same run do happen, so a script can build its scratch files and clean them up with `defer`, as above.
- The [dependency check](#dependencies) is skipped, and the constant `dry_run` is `true`.
- `http.post` counts as a write: it is only shown, and returns `""`.

## `embed`

`embed("file")` reads a text file at compile time and gives its contents as a `str`, so the generated script stays a single file:

```text
let template = embed("templates/gitconfig")
fs.write(dirs.home() / ".gitconfig", fmt(template, name, email))
```

The path is fixed text, relative to the folder of the `.nalu` file. A missing file, a path that isn't fixed text, or a file that isn't UTF-8 is `E053`.

## Several files: `use`

```text
// deploy.nalu
use "lib/services.nalu"
use "lib/text.nalu"

param stage: str = "dev"

let api = Service { name: "api", port: 8080 }
print(shout("deploying {api.name} to {stage}"))
```

`use "file.nalu"` brings in the `fn`, `struct`, `enum` and `test` declarations of another file:

- `use` lines go at the start of the file, before `param` (`E005`). The path is fixed text, relative to the folder of the file with the `use`.
- A used file can only declare `fn`, `struct`, `enum` and `test` (`E055`); it can `use` other files in turn. Each file is loaded once, however many files use it.
- Everything is compiled together: `nalu build` still writes one self-contained script per target, so nothing extra has to be copied to the machine that runs it.
- Names share one space: two files that declare the same name are `E003`.
- `nalu test lib.nalu` runs the tests of a library; `nalu test script.nalu` also runs the tests of the files it uses.
- In the editor, hover, completion and go to definition follow names into the used files.

A library looks like this:

```nalu
// lib/text.nalu
fn shout(s: str) -> str {
    return "{s.upper()}!"
}
```

## Tests

```nalu
fn divide(a: int, b: int) -> int {
    if b == 0 {
        fail "division by zero"
    }
    return a / b
}

print(divide(10, 2))

test "divides integers" {
    assert divide(10, 3) == 3
}

test "division by zero fails" {
    assert_fails(divide(1, 0))
}
```

```console
$ nalu test .
ok      divides integers
ok      division by zero fails
2 test(s), 0 failure(s)
```

- `test "name" { … }` appears only at the top level. `assert cond` and `assert_fails(call)` appear only inside a test (`E060`).
- `assert` fails the test and shows the condition: `FAILED  name: assert failed: divide(9, 3) == 4`.
- `assert_fails` takes a call or a command, and passes when it fails. On something that can never fail it is `E060`.
- An unhandled failure inside a test fails that test with the error's message: `FAILED  name: division by zero`.
- **Packages.** Tests usually live next to the script: `nalu test` compiles `x_test.nalu` together with `x.nalu` in the same folder, so the tests see its functions and types. A file with its own `test` blocks is a package by itself. A folder can hold several independent packages. See [`../examples/release_test.nalu`](../examples/release_test.nalu), which tests [`release.nalu`](../examples/release.nalu).
- **What runs.** Only the declarations run: functions and types, parameters with their defaults (required ones get an empty value), and top-level `let`/`var` whose value is a literal or an expression without calls. Commands, calls and other top-level statements don't run, so a variable set by a call is empty in tests. Keep test data inside the tests.
- The output has one line per test (`ok      name` or `FAILED  name: …`) and a summary, `N test(s), M failure(s)`. The exit code is 1 if any test failed.
- `nalu check x_test.nalu` checks the package, so names from `x.nalu` are known.

## The `nalu` tool

| Command | What it does |
|---|---|
| `nalu run x.nalu [-- args…]` | compiles for this system and runs the script with the arguments |
| `nalu build x.nalu [--target a,b] [-o dir]` | writes `x.linux.sh` and `x.macos.sh` (executable), `x.windows.ps1` (ASCII with CRLF, so `irm … | iex` works) and a `x.windows.cmd` launcher; the default is every target, into `dist` |
| `nalu check x.nalu [--json] [--explain]` | checks only: errors and warnings for all three targets; `--explain` also lists every place that can fail ([details](#seeing-what-can-fail-nalu-check---explain)) |
| `nalu check --stdin x.nalu […]` | the same, reading the source from standard input (for editors with unsaved files) |
| `nalu fmt <file\|folder>… [--check]` | formats `.nalu` files in place; folders are searched recursively, skipping `target`, `dist` and hidden folders; `--check` changes nothing and lists the files that would change |
| `nalu fmt --stdin x.nalu` | formats standard input to standard output |
| `nalu doc [name…] [--all]` | documentation for a module (`fs`), function (`fs.copy`), type (`str`), member (`str.split`) or keyword (`catch`); with no name, the overview; `--all` prints the whole standard library reference as Markdown ([stdlib.md](stdlib.md)) |
| `nalu emit x.nalu [--target T] [--ir]` | prints the generated script (or the intermediate representation) for one target, by default this system |
| `nalu test [folder\|file] [--target T]` | runs the `test` blocks of each package (see [Tests](#tests)); the default folder is `.` |
| `nalu ide <query> x.nalu --at LINE:COL [--stdin]` | editor queries, as JSON: `hover`, `complete`, `signature`, `definition`, `context` |
| `nalu --version`, `nalu --help` | |

- **Targets** are `linux`, `macos` (also `darwin`, `mac`) and `windows` (also `win`).
- **Exit codes:** 0 when everything is fine, 1 for compile errors or failed tests, 2 for wrong usage. `nalu run` exits with the script's own code.
- `nalu run` needs `bash` (`/bin/bash` or on `PATH`) or, on Windows, `pwsh` or `powershell`; the environment variable `NALU_PWSH` picks a specific PowerShell.
- `nalu fmt` doesn't write files with syntax errors: it prints the diagnostics and exits with 1.
- `nalu doc` with an unknown name suggests the closest one and exits with 1.
- `nalu check` prints `ok: x.nalu` when there is nothing to report.

`nalu check --json` prints a list of `{file, line, column, severity, code, message, help}`, where `help` may be `null`:

```text
[
  {"file":"x.nalu","line":1,"column":9,"severity":"error","code":"E040","message":"`catch` after something that cannot fail","help":"remove the `catch …`"}
]
```

With `--explain`, it prints an object, `{diagnostics, fallible, fallible_fns}`, where each item of `fallible` is `{file, line, column, end_line, end_column, what, effect}`.

The [VS Code extension](../editors/vscode/README.md) runs these commands as you type. For AI assistants, [`../llms.txt`](../llms.txt) has the language on one page; after generating Nalu, run `nalu fmt` and `nalu check`.

## Diagnostics

Every diagnostic has a stable code: `E` for errors, `W` for warnings. Each one shows the code and message, the file, line and column, the source line with a marker under the problem, and, when possible, a `help` line with the fix:

```console
$ nalu check ready.nalu
error[E040]: `catch` after something that cannot fail
  --> ready.nalu:2:10
  |
2 | let ok = a == 1 catch a == 2
  |          ^^^^^^
  = help: for a logical "or" between conditions, use `||` (`a || b`); `catch` only handles failures
```

The parser recovers from errors, so one run reports several. Warnings don't stop `nalu build` or `nalu run`.

| Code | When |
|---|---|
| `E001` | a name, field, method or module function doesn't exist (with "did you mean"); also a feature removed in v1 (see below) |
| `E002` | changing a `let`, a parameter, a loop variable or `self` |
| `E003` | declaring a name, type, field, case or function twice |
| `E004` | using a reserved name (`os`, `err`, `fs`, `or`…) |
| `E005` | syntax error: unexpected token, unclosed text or brace, bad number or duration, unknown escape, `param` after other code |
| `E006` | a form from another language or from older Nalu, with the Nalu form in the hint (see below) |
| `E010` | wrong type: in an operator, assignment, argument, condition, `return` or `if`/`match` branch |
| `E011` | `==` or `<` between different types, collections, structs or secrets |
| `E012` | wrong arguments: missing, extra, unknown name, repeated, positional after named, a required parameter after an optional one; missing or unknown struct fields; the `fmt` placeholder count; a lambda with more than one parameter; bad `retry` or `parallel` options |
| `E020` | mixing `duration` and `int` |
| `E021` | a bare duration as a command argument |
| `E022` | a list, map or struct in interpolation |
| `E030` | an expression that does nothing |
| `E031` | a `match` that doesn't cover every case (lists the missing ones), or an arm that is never reached |
| `E032` | a function with a return type where some path ends without `return` |
| `E033` | a lambda outside an argument, a lambda that changes outside variables, a function used as a value |
| `E040` | `catch` after something that can't fail |
| `E041` | `try` without `catch` |
| `E042` | a list mixed with text in a command word |
| `E043` | `/` with `str` on the left |
| `E044` | `{ … }` or `{}` without a known type |
| `E045` | a `parallel` body that changes an outside variable or uses `return` |
| `E046` | `break`, `continue`, `return`, `self` or `err` where they don't apply |
| `E050` | a `secret` becoming text, or a `secret` parameter with a default |
| `E051` | `os` compared with something that isn't a system |
| `E052` | `native` without both shells, with an unknown key, or with interpolation |
| `E053` | `embed` of a missing file, a path that isn't fixed text, or a file that isn't UTF-8 |
| `E054` | a `regex` pattern that isn't fixed text, isn't valid, or (for `find`, `find_all`, `groups`, `replace`) can match the same text in more than one way |
| `E060` | `assert` or `assert_fails` outside a `test`; `assert_fails` on something that can't fail |
| `E055` | `use` of a file that doesn't exist, or a used file with something other than `fn`, `struct`, `enum` and `test` |
| `E090` | a planned feature: lists of maps, maps of maps, three levels of lists, a list field whose items have map fields, `parallel for` with an index or returning collections, a struct pattern inside a struct pattern, the `pkg` module |
| `E999` | an internal compiler error; please report it with the file that caused it |
| `W001` | a variable that is never read |
| `W002` | a `param` that is never used |
| `W010` | a program that doesn't exist on one of the targets |
| `W011` | a `secret` as a command argument |
| `W012` | `catch ignore` on a command that changes files |

### Forms that don't exist

When you write something from another language, or from Nalu before v1, the compiler names the Nalu way:

| You write | Code | Write instead |
|---|---|---|
| `a or b`, `a and b` | `E006` | `a \|\| b`, `a && b` |
| `not a` | `E006` | `!a` |
| `} elif c {`, `for (i = 0; …)` | `E006` | `} else if c {`, `for i in 0..n` |
| `x ?? fallback`, `null`, `nil`, `None` | `E006` | `x catch fallback` |
| `try f()`, `throw "x"`, `raise` | `E006` | `f()` (it propagates), `f() catch …`, `fail "x"` |
| `fn f() throws`, `fn f(): int` | `E006` | `fn f() -> int` |
| `str[]`, `map<str, int>` | `E006` | `[]str`, `map[str]int` |
| `fail("message", code: 3)` | `E006` | `fail "message", code: 3` |
| `const`, `func`, `function`, `def` | `E006` | `let`, `fn` |
| `switch`, `case` | `E006` | `match`, `pattern =>` |
| `for x of xs`, `for i = 0; i < n; i++` | `E006` | `for x in xs`, `for i in 0..n` |
| `x++`, `a ? b : c`, `;`, `import`, `print "x"` | `E006` | `x += 1`, `if a { b } else { c }`, a new line, nothing, `print("x")` |
| `m.get(k)`, `m.set(k, v)` | `E001` | `m[k]` (can fail), `m[k] = v` |
| `s.is_empty()`, `xs.is_empty()` | `E001` | `s == ""`, `xs.len() == 0` |
| `n.to_str()` | `E001` | `"{n}"` |
| `p.exists`, `p.is_dir`, `p.is_file`, `p.size`, `p.modified` | `E001` | `fs.exists(p)`, `fs.is_dir(p)`, `fs.is_file(p)`, `fs.size(p)`, `fs.modified(p)` |
| `path.join(a, b)` | `E001` | `a / b` |

  --> old_api.nalu:2:17

## Limitations

- No floating-point numbers.
- Collections nest one level: lists of lists of scalars and maps with list values. Lists of maps, maps of maps and deeper nesting are planned (`E090`).
- A mutating method on a nested value (`groups[k].push(x)`, `rows[0].pop()`) works as a statement or as the whole value of `let`, `=` or `return`; inside a larger expression (`print(rows[0].pop())`) it is `E002`.
- The `pkg` module is planned (`E090`). Until then, use a command with `$` or a `native` block.
- On Windows, `parallel` tasks that call `sys.cd` or `env.set` run one at a time, and starting the runspaces costs a few hundred milliseconds per `parallel`.
- Integers are 64-bit and overflow isn't checked, so results past the limits differ between targets. `to_int()` rejects numbers out of range.
- `json` is parsed by the script itself, with no `jq` or Python, which suits API responses and configuration files rather than large documents.
- On Linux and macOS, `http` uses `curl`; `wget` is enough only for a plain `GET` without headers or a token.
- On macOS, `time.now_ms()` gets milliseconds from the `perl` that ships with the system; without `perl` it has one-second precision, because the BSD `date` has no `%N`.
- A `native` block that changes `IFS` globally can break how the Bash scripts pass lists to functions.
- Lambdas exist only as arguments and only read outside variables.

## Keywords and grammar

### Keywords

The 27 keywords:

```text
let  var  fn  return  struct  enum  param
if  else  for  in  while  match  break  continue
fail  catch  ignore  try  defer  parallel  retry  native
test  self  true  false
```

### Reserved names

These aren't keywords, but they can't name your variables, parameters, functions or types (`E004`). Struct fields can use them.

| Group | Names |
|---|---|
| constants | `os`, `dry_run`, `args`, `err`, `self` |
| built-ins | `print`, `fmt`, `exit`, `fail`, `retry`, `secret`, `embed`, `assert`, `assert_fails` |
| logic words from other languages | `or`, `and`, `not` |
| modules | `archive`, `dirs`, `encoding`, `env`, `fs`, `hash`, `http`, `json`, `log`, `math`, `path`, `pkg`, `proc`, `regex`, `sys`, `time`, `ui` |
| `param` names only | `verbose`, `help` |

### Grammar

A summary in EBNF. `NL` is a significant line break; `NAME`, `STRING`, `INT`, `DURATION` and `TEXT` (a run of characters in a command) are tokens.

```text
file        = (use NL)* (param NL)* (item NL)*
use         = "use" STRING
doc         = ("///" TEXT NL)+
param       = doc? "param" NAME ":" type ("=" expr)?
item        = fn | struct | enum | test | stmt
fn          = doc? "fn" NAME "(" (fn_param ("," fn_param)*)? ")" ("->" type)? block
fn_param    = NAME ":" type ("=" expr)?
struct      = "struct" NAME "{" ((field | fn) NL)* "}"
field       = NAME ":" type ("=" expr)?
enum        = "enum" NAME "{" NAME (("," | NL) NAME)* "}"
test        = "test" STRING block
block       = "{" (stmt NL)* "}"
type        = "str" | "int" | "bool" | "path" | "duration" | "secret" | NAME
            | "[]" type | "map" "[" type "]" type

stmt        = decl | assign | expr
            | "fail" fail_args | "return" expr? | "break" | "continue" | "exit" "(" expr? ")"
            | "for" NAME ("," NAME)? "in" expr block | "while" expr block
            | "defer" expr | native | "assert" expr | "assert_fails" "(" expr ")"
decl        = ("let" | "var") NAME (":" type)? "=" expr
assign      = place ("=" | "+=" | "-=" | "*=" | "/=" | "%=") expr
place       = NAME | place "." NAME | place "[" expr "]"
fail_args   = expr ("," "code" ":" expr)?
native      = "native" "{" "bash" ":" STRING NL "powershell" ":" STRING NL? "}"

expr        = input ("catch" handler)?
handler     = "ignore" | "fail" fail_args | block | expr
input       = or_expr ("|" command)?
or_expr     = and_expr ("||" and_expr)*
and_expr    = compare ("&&" compare)*
compare     = range (("==" | "!=" | "<" | "<=" | ">" | ">=") range)?
range       = sum ((".." | "..=") sum)?
sum         = term (("+" | "-") term)*
term        = unary (("*" | "/" | "%") unary)*
unary       = ("-" | "!") unary | postfix
postfix     = primary ("." NAME | "(" args? ")" | "[" expr "]")*
args        = (NAME ":")? expr ("," (NAME ":")? expr)*
primary     = literal | NAME | "self" | "(" expr ")" | list | map | struct_lit | lambda
            | if | match | "try" block | retry | parallel | command | capture
literal     = STRING | INT | DURATION | "true" | "false"
list        = "[" (expr ("," expr)* ","?)? "]"
map         = "{" (expr ":" expr ("," expr ":" expr)* ","?)? "}"
struct_lit  = NAME? "{" (".." expr | NAME ":" expr) ("," (".." expr | NAME ":" expr))* ","? "}"
lambda      = (NAME | "(" NAME ")") "=>" (expr | block)
if          = "if" expr block ("else" (if | block))?
match       = "match" expr "{" (arm NL)* "}"
arm         = pattern ("|" pattern)* ("if" expr)? "=>" (block | stmt)
pattern     = literal | "-"? INT (".." | "..=") "-"? INT | NAME | "_"
            | NAME "{" (NAME ":" pattern ("," NAME ":" pattern)*)? "}"
retry       = "retry" "(" expr ("," "every" ":" expr)? ")" block
parallel    = "parallel" ("(" "max" ":" expr ")")? ("for" NAME "in" expr block | block)

command     = "$" pipeline                // up to the end of the line, ` catch `, `//` or a `{` that ends the line
capture     = "$(" pipeline ")"
pipeline    = (word | redirect)+ ("|" (word | redirect)+)*
word        = (TEXT | "'" TEXT "'" | '"' TEXT '"' | "{" expr "}")+
redirect    = (">" | ">>" | "2>" | "2>>" | "<") word | "2>&1"
```

In the condition of `if` and `while`, the list of a `for`, the subject of a `match` and the `if` of an arm, a `{` starts the block rather than a struct literal (a map literal such as `{ "a": 1 }` is still a map). In the condition of `if` and `while`, a `$` command tests its exit code.
